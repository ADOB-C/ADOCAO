## Audio System

### audio-as-chart（每层一个采样的巨型谱）

`--force-hitsound raw-pcm`（向导 Override 下拉里也有）走**直通**，不做 hitsound 混音：
`Timeline::buildRawPcm()` 把"每层音量"当 PCM 采样值导出（1 层 = 1 采样，采样率 = `bpm/60`，
映射与 `Song.adofai` 的 `volume = int16 / 655.36` 严格互逆），`HitsoundManager::preSynthesizeRawPcm()`
线性重采样到设备采样率（48 kHz）再复制成双声道。249 s 的谱导出只要 9–25 ms。

为什么必须直通：那种谱是"**每个采样一个 Kick**"。Unity.wav_rate 实测 10,993,500 命中 / 249.3 s =
44.1 kHz，而 `Kick.wav` 有 9,499 帧（215 ms）→ **每个输出采样上叠 ~9,499 次相加**，而混音规则是
"每次相加都 clamp 到 ±32768"（这条对普通谱是忠实度要求，不能动）→ 必然整段顶轨，示波器上就是
一排单向尖峰。被删掉的 float + 软限幅版本当年"恰好"掩盖了它，所以这类谱在优化后听起来才崩。

**同时修掉一个长期存在、对拍看不见的 bug**：`processActions` 用 `a.val1 > 0` 判断"这个 SetHitsound
有没有写音量"，于是**负音量和 0 都被替换成 settings 默认（100）**。Unity.wav_rate 的 10,993,500 个
`hitsoundVolume` 里负 5,471,227、零 50,855 —— 全被吃掉，半个波形变成满刻度。改成用
`FastAction::flag` 携带存在性（负/零原样保留）。实测：满刻度占比 **50.25% → 0.05%**、RMS
**0.7737 → 0.4392**、min **0 → -1.0**，静音数 50,856 与文件里的零**逐一对上**。

教训：这类 bug 在**两条解析路径共用的代码**里，逐位对拍摘要永远一致 ✗。所以补了**直接语义断言**
`rawVolumeSemanticsSelfTest()`（负/零音量必须原样落到 `tileHitsoundVolumes`，旧路径+快路径都查），
并做了负向对照：把 `flag` 改回 `> 0` 时它立刻报 `floor 1: 期望 -33.50，实际 100.00` ✓。

**自测**（2026-10-11）：`tests/raw_pcm_test.cpp`（ctest `raw_pcm`）—— 用 `tests/charts/diag_wav_rate.adofai`
（**整谱就是 Do-Mi-Sol 波形**，每砖一个采样）验三层：① `buildRawPcm` 认谱（rate/采样数）；
② **负向对照**：普通打拍音谱必须被拒（否则会被当 PCM 播成噪声）；③ 重采样到设备率后，
Do/Mi/Sol 三个频率的能量**同时**远高于对照频率（实测 0.296/0.293/0.291 vs ~0）。

**另一个坑（同一天修的）**：`m_tileStartTimes` 的最后一格是 `calculateTilePositions()` 追加的
**合成 extra 砖**（无限旋转参考），它**不是谱面里的砖，不该产生打拍音** —— 混音循环按
`tileStartTimes().size()` 排时刻，于是**每张谱末尾都多响一下**（对拍看不见、像素门槛也看不见）。
现在走 `Timeline::realTileCount()`（真实层数 = `angleData.size()`），两种谱型都按它排。

### "拿 Kick 打出和弦"（相位编码节奏）
每砖放的是同一段打击音色，音高**不由音色决定，而由重复频率决定**（137 下/秒听起来就是 137 Hz 的
"蚊子声"）。要让耳朵听到 Do-Mi-Gol：把击打时刻放在三个频率网格的**并集**上（三条脉冲列相加
= 三条谱线）。

**参考谱实测**（`The Moon - Coal/level.adofai`，就是"能听到和弦"那一族；用户 2026-10-11 指认）：

| 项 | 实测 |
|---|---|
| BPM | **14817.6 恒定**（`SetSpeed` 只有 8,457 个，是段落级的，不是逐砖）|
| 砖 / 事件 | 600,538 砖；**303,540 个 Twirl**（约每 2 砖一个）；音色 Kick、音量 50 |
| 每砖时长 | 中位 **4.56 ms**（≈ 1 拍）、等效**击打频率中位 ~220 Hz** —— 音高**就是击打频率** |
| 几何转角 | 均值 **92.7°**、其中 1/3 的砖 \|转角\| < 30°；`angleData` 均值 157 |

**不要用逐砖 SetSpeed**（我一开始就是这么写的，被指出来了）：它会连累所有按拍计时的东西
（BPM 显示、`beatsAhead/Behind`、以及 audio-as-chart 的采样率 `bpm/60` 是否成立），而且
21 亿层目标下每砖一个事件也吃不消。正确做法是**恒定 BPM + Twirl 选边**：

    delta = (angleData[i-1] + 180 - angleData[i]) mod 360        // 与 Timeline 一致
    CW  : duration = delta/(3 x BPM)     = (180 - t)/(3B)        // t = 几何转角
    CCW : duration = (360 - delta)/(3B)  = (180 + t)/(3B)

也就是说：**同一对角度**（同样的 |t| = 同样的"直不直"）在 Twirl 的两侧给出载波两侧的偏差 ——

    d = c ± |t|/(3B),      c = 60/BPM（载波 = 一拍）

于是 **Twirl 就是"偏差的符号位"，角度只负责偏差的大小**：想让这一砖比一拍短就走 CW、
比一拍长就走 CCW，而 |t| 只由"差多少"决定。|t| 被时刻锁死（和弦上平均 ~74°），
**能自由选的只有符号** —— 用户 2026-10-11 的第二条指点就在这里：

> **用 Twirl 固定一个大体的方向。**

做法有两种，后者更好（用户 2026-10-11 的第四条）：

1. **bang-bang 控制**：记住累计朝向 H，`H > 0` 选负转角、`H ≤ 0` 选正转角，把 H 拉回 0。
   实测路径是一条 1060 x 29 砖的长带（不再是花），平均角度 177.6。
2. **利用最小公倍数（LCM）**（推荐，本仓库现在用的）：三音取**纯律 4:5:6**
   （f0 = 65.4075 Hz）时它们有**精确的公共周期** T = 1/f0 = **15.2888 ms**
   （周期内 4+5+6-1 = 11 个点、12 段），于是：
   * 把 Twirl 的符号模式也做成**逐周期重复**，并解一个 ±号组合让**每周期净转角 = ±360°**
     （绕**整整一圈** ⇒ 每个公共周期收成一个**闭合的环**）；
   * 再把整体角度平移一下，让**每个 LCM 边界正好落在 180°**（用户要求）。

   > 参考视频（B 站 `BV1soTk6SErK`，星陨_OwO，11.45 s，简介"纯打击音,音乐音量为 0"）
   > 抽帧看得更清楚：砖路就是一串**环**（`build/ref/f_11.png` 里一圈约 14 砖）沿着一条
   > 弧线漂移，环与环之间是直条。它的音频谱峰是 **~58.5 Hz 的谐波**（4/5/6 那一组，
   > 比我们低一个八度）+ 第二组谱线 —— 也就是同一套做法，而且是**双线**（两个声部）。
   > 换句话说：净转角取 **±360（成环）**、不是 0（成锯齿直线）。

   `diag_chord` 实测：**LCM 边界 164 个（每 12 砖），最大偏离 180° = 0.0003 度**；
   转角序列**逐周期逐位重复**；每周期净转角 **±360°** ⇒ 砖路是**一串闭合的环**沿一个
   方向漂移（放大见 `build/diag/chord_zoom.png`，与参考视频的"环串"一致；转角大小仍被
   时刻锁死：|转角| 均值 80.2°）。

**`tests/charts/diag_chord.adofai` 实测**（ctest `kick_chord`）：纯律 4:5:6
（261.63 / 327.04 / 392.44 Hz）、恒定 BPM 31200（一拍 1.923 ms）、**656 个 Twirl、0 个 SetSpeed**；
1968 击落在三网格的并集上、最大时刻误差 **0.1 us**；**LCM 边界 164 个（每 12 砖）全部落在 180°**
（最大偏离 0.0003°）、**每周期净转角 ±360°**（收成环）、转角序列逐周期重复；
混音后三条谱线各高于本底中位数 **6 倍以上**（0.012 / 0.115 / 0.091 —— 强弱就是每周期击打
密度 4:5:6 乘 Kick 的频谱包络）。放大看就是"一串环"（`build/diag/chord_zoom.png`）。

⚠️ **转角的大小躲不开、只有符号能选**：任意击打间隔 ⇒ |转角| = 3B|d - c| 在 0~180° 上近似均匀
（平均 ~90°，参考谱的 92.7° 就是这个）。所以"展开"能做的是**方向**（bang-bang 固定大方向，
长带而不是花），做不了"每砖都走直线" —— 那要求所有间隔都等于载波（只有一个音高）。
参考谱里那条特别干净的长弧，是它音频本身平缓（慢扫频）的段落：那里的偏差小、砖路自然舒展。

另一条路（**用户明确不采用**："类 PCM 编码"）：`Unity.wav_rate.adofai.xz` 实测 10,993,499 个
`SetHitsound`（Kick + 逐采样音量 = 把波形当音量写进每一砖），BPM 恒定、无 Twirl、无 SetSpeed。
我们只把它当 `diag_wav_rate` 的对照 fixture，不作为推荐做法。
