# 2e9：本项目的当前目标

> **一句话**：让 ADOCAO 能在普通机器上打开**约 21 亿层（2³¹−1 = 2,147,483,647）**的谱面 ——
> 加载不 OOM、能 seek 到任意层、播放不掉帧 —— 而且**常驻内存与层数 n 解耦**（n 从 1e6 长到 2³¹，
> RSS 基本不变），同时**现有的所有验收在每个阶段保持绿色**。
>
> 本文件是**目标与验收**的单一出处；`docs/scale-1e8-to-2e9.md`（39 KB）是**分析/实测**长文，
> `TODO.md` 是**任务清单**，`docs/adocao-format.md` §8 是**容器侧设计**。三者不重复。

---

## 1. 为什么是 2³¹−1

* 它是**32 位有符号**的天然上限：越过它，一切 `int` 索引、`GLsizei` 单次绘制、`FastAction::floor`
  都得换类型。所以"摸到 2³¹−1"= **把 32 位假设全部清算干净**，是个有明确边界的目标，而不是"越大越好"。
* 现实参照：本地最大的谱 `primer-final` 是 **6,841 万层 = 目标的 3%**（`docs/scale-1e8-to-2e9.md` §14）；
  MYC 677 万层、audio-as-chart（`Unity.wav_rate`）1,100 万层且**逐采样事件**。3% 是实验室的极限，
  所以边界的验证**只能靠纯函数单测 + 反面对照**（见 §5 纪律）。

## 2. "做到了"的可测定义（DoD）

| # | 判据 | 怎么量 | 现状 |
|---|---|---|---|
| D1 | **内存与 n 解耦**：n 从 6.8e6 → 6.8e7 → 2³¹，常驻 RSS 基本不涨（涨的只有 checkpoint 索引与窗口） | 真无头加载 + 峰值 RSS（`adocao image` 只加载不出图） | ❌ 现在线性（MYC **212 B/层**、峰值 1436 MB） |
| D2 | **任意层 O(1)~O(log n) seek**：跳到第 k 层不需要重放全谱 | 从 checkpoint 重建窗口，量 seek 延迟 | ❌ 无 checkpoint |
| D3 | **播放预算**：可见实例 ≤ 60 fps 的容量线（重绘口径 **159K**/几何口径 489K） | `docs/scale-1e8-to-2e9.md` §8 的标定（34.12 ns/实例几何下限、100~105 ns 重绘受限） | ⚠️ 容量公式已有，未接窗口化 |
| D4 | **零行为变化**：现有验收全绿 —— ctest（当前 18 个）、40 份 fixture 逐位对拍、**像素门槛 51/51 逐字节**、core-purity、shader-fallback、无绝对路径 | 每阶段全跑 | ✅ 基线 |
| D5 | **规模律可复现**：每条规模结论都留下"可重跑的命令 + 数字 + 证据等级" | 文档留痕 | ✅ 本仓库惯例 |

**目标态的算账**（`docs/scale-1e8-to-2e9.md` §3/§8.2）：

* 常驻只留**稀疏随机访问索引**：若保留"每层 O(1)"契约，最小集 ≈ **36 B/层**（position 16 + times 8 +
  angles 8 + BPM 4 + CW 1 bit）—— 2³¹ 层就是 **77 GB** ✗，所以**不能靠"每层都常驻"**；
* 真正的出路是 **每 4096 层一条 37 B 的 checkpoint（= 0.009 B/层）+ 窗口重算**：
  2³¹−1 层的索引只要 **19.4 MB**，其余（angleData / 时间 / actions / 每砖数组）都可窗口化或可重算。

## 3. 现状基线（2026-10-11）

**靶场（本地真谱）**

| 谱 | 层数 | 特点 |
|---|---|---|
| `primer-final` | 6,841 万（**3%**） | 最大；修完 `Tile` 容量 2× 坑后 GUI 播放换出量 +296 MB → **0**，峰值 RSS 5.9 GB |
| `Unity.wav_rate`（audio-as-chart） | 1,100 万 | **逐采样** `SetHitsound`（1,099 万事件）、文本 1.47 GB |
| MYC | 677 万 | 事件密度 ≈0.9/层；真无头峰值 **1436 MB / 212 B/层**（mesh ≈430 MB）|
| angles360 / The Moon | 万级 | 人工/正常谱参照 |

**每层字节账**（实测，`docs/scale-1e8-to-2e9.md` §2）

* `Timeline` 恒定 7 支数组 = **32.125 B/层**（`tileStartTimes` 8 B 起）；
* 加载期峰值 **212 B/层**（MYC 口径）→ 2³¹ 层 ≈ **455 GB** ✗ —— 这就是 D1 要打的那一仗；
* 已经省掉的：层距两条 `vector<float>`（8 B/层，2³¹ 层 = 17 GB）→ 层数 + 两个标量；
  `Tile` 容量 2× 坑（24 B/层 → 48 B/层）、`setSpeedByFloor` 无条件 1.2 GB、`angleData` 预留按密度估。

**时间账**：MYC 无头 **1.39 s / 1473 MB**（`parseNumber` 的 `e` 边界 bug 修完后的数字；修前 4.60 s / 4943 MB）。
`actions` 分块并行阈值 32 MB~768 MB 在大谱上**永远不生效**（§5.4）。

**32 位账**：`#0 阶段 1–2 已完成` —— `core/util/CountLimits.hpp`（`fitsInt32`/`toInt32Checked`）
+ `tests/limits_test.cpp`（ctest `limits`，13 条断言含**反面对照**），§6 表里所有 `(int)size()` 站点
改成"int64 算、收窄前显式判、装不下就 `LOG_E`"。**Timeline 现在对 >int32 层是明确拒绝**（不是静默坏）。
**阶段 3 未做**：循环索引、`floor` 自身的类型（`FastAction::floor` 一族才是最深那层假设）、`GLsizei` 分批。

**容器账**（`.adocao` v2 已落地，v3 只落了诊断）：

| 谱 | 明文 | xz -9e | `.adocao` | vs xz |
|---|---|---|---|---|
| MYC | 641 MB | 2.18 MB | **6,120 B** | **356×** |
| The Moon | 16.4 MB | 122 KB | **3,544 B** | **34.4×** |
| Unity.wav_rate | 1.47 GB | 49.4 MB | **20.1 MB**（1.92 B/层）| **2.34×** |
| かめりあ - QuomodocunquizE | 3.62 MB | 136 KB | **108,928 B** | **1.25×** |

**"最先不可行的一环"（2026-10-15 已修，见 §4 ①）**：`.xz` 的**流式窗口路径会静默放弃、退回整份解压** ——
`Unity.wav_rate` 上默认 `ADOCAO_WINDOW_KB=4096` **3/3 拒收**（8192 才收），代价 **+1271 ms / +482 MB**；
对 1e8 层文本而言，"退回去做一次连续分配"等于**在任何一层建起来之前就必然失败**
（`docs/scale-1e8-to-2e9.md` §4）。

**真因（2026-10-15 定位并修复，`strtod` 那条归因是错的）**：`parseNumber` 的**指数回退**。
当半窗正好在 `e` / `e±` 之后用完时，它把 `q` 退回指数标记、**当作"光秃秃的 e 不算指数"**，
于是 ① 提交了一个**截断错值**（`4.547473508864641` 而不是 `4.547473508864641e-13`）；
② 残留的 `e` 被 carry 到下一窗，而下一窗的第一个字节就是 `e`（`parseNumber` 立刻失败）
→ 整窗原样 carry → 半窗被自己占满 → `ArchiveStream::stuck()` → 静默回退整份解压。
audio-as-chart 的层值**全是指数写法**，所以必然命中；8192 KB 只是换了边界相位、恰好绕开。
现在"缓冲区在 `e`/`e±` 后用完"直接返回 false（= 这里没有完整数字），窗口会把它 carry 到下一窗重放。
永久用例：`windowExponentBoundarySelfTest()`（定点相位 + 8 种半窗相位的数字形式扫描，逐位对拍）。

## 4. 阶段的顺序（依赖决定，别跳）

按 `docs/scale-1e8-to-2e9.md` §8 的"必须做的顺序"，加上容器侧两半：

| 序 | 做什么 | 为什么在这个位置 | 验收 | 现状 |
|---|---|---|---|---|
| ① | **修窗口路径**（让流式窗口真的被用上） | 否则 1e8 层压缩谱在解析任何一层之前就死 | 默认 `ADOCAO_WINDOW_KB` 在大谱上不再退回整份解压；日志无 "回退整份解压" | ✅ 2026-10-15（真因 = `parseNumber` 的指数回退，不是 `strtod`；`Unity.wav_rate` 上 4096+`WINDOW_REQUIRE=1` **3.67 s / 2243 MB** ≈ 8192 的 3.71 s / 2252 MB，退回整份是 4.73 s / 3696 MB；两条路的 `.adocao` 打包**逐字节相同** 21,079,240 B）|
| ② | **容器 v3 ⑥ 分块 + ⑧ `Derived` checkpoint**（块自包含 + 块内自选，间隔对齐 **4096**） | 加载器窗口化要消费"按 4096 层寻址"的地基 | 分段型实测 **1.66~3.29×**；v3 编码器自检（编完解回来逐位比） | ✅ **⑥⑧ 均已完成（2026-10-15）**：`AdocaoBlocked` + `ctest adocao_blocked`；v3 文件**大小与 v2 完全相同**（MYC 6120=6120、The Moon 3544=3544、Unity 21,079,240）；分段型**编码级** 3.87/2.19/1.70×（§8.3 口径），但**存储级**被段级 zstd 吃掉（1.00/0.97/0.96×）→ 规则改为"≥128 MB 裸数据**强制分块**、其下取最小"；**⑧** `AdocaoCheckpoints` + `ctest adocao_checkpoints`：每 4096 层一条 **96 B** 快照（base/cum/time/bpm/lastAngle，f64），`adocao pack --checkpoints` 写出（默认关 → 默认 v3 文件仍与 v2 同大小）；**§8.10⑥ 逐位对拍**：The Moon 147 条 / 重算 602,112 层 0 不一致、MYC 1654 条 / 重算 6,774,784 层 0 不一致；**反面对照**：baseX 动 1 ULP → 1697/4096 层立刻变红。成本 0.0045 B/层（2³¹ 外推 ≈9.8 MB）|
| ③ | **每砖结构窗口化 + 稀疏 checkpoint**：`Tile`/`tileBPMs`/`FastAction`/**timeline** | D1 的正主；把常驻从 212 B/层降到 O(窗口 + 索引) | RSS **不随 n 线性**；2³¹−1 层索引 ≈ **19.4 MB** | 🔶 **重算 + 索引已完成（2026-10-15）**：`AdocaoWindow::computeFloorWindow` 从 checkpoint + 一块 angleData + 这一块的事件重算出 `Tile::position/direction`、`tileBPMs`、`tileStartTimes`，**与全量加载逐位 memcmp**（The Moon 147 窗 / MYC 1654 窗 **0 不一致**；反面对照：baseX 动 1 ULP、bpm×1.5、cw 翻转 → 立刻变红）；`ActionIndex` 段（8 B/4096 层 → 2³¹ 外推 **4.0 MB**，zstd 后 ≈0.7 MB）逐块与全量扫描一致。**装配也已完成**：`FloorWindowSource` 从容器按块取（新增 `getSectionView`，reader 改成**段载荷按需解压**；稀疏列靠 `ActionIndex` 的 used 起点做到 O(1)），The Moon 147 块 / MYC 1654 块 —— 角度窗口、事件窗口、位置方向、时间、BPM **全部 0 不一致**、块块都有快照；`--walk` 实测峰值 RSS **MYC 6.4 MB / The Moon 5.6 MB**（层数 11×，峰值只涨 0.8 MB）。**未做**：`LevelData` 仍是全量加载、按需开窗的消费方（渲染/剔除/时间线）还没接 → **D1 对"产品常驻内存"仍不能宣称**（能宣称的是"加载路径与 n 解耦"）|
| ④ | **剔除加空间索引（BVH/网格）** | 现在是 O(n)（1~4 ns/砖）→ 1e8 层 0.1~0.4 s、2³¹ 层 2~8 s ✗ | 剔除成本 ∝ 可见 | ❌ |
| ⑤ | **Z 换成不依赖深度缓冲分辨率的排序** | `tileZForIndex` 在 120 万层就开始同深度相邻砖（7M 时 **78.4%**），遮挡胜负由 `unordered_map` 迭代序决定 | 跨规模遮挡稳定（不再"反转顺序差 102~278 px"） | ❌ |
| ⑥ | **索引全面 64 位**（`#0` 阶段 3）+ `GLsizei` 一次 draw 拆多次 | 最深的那层 32 位假设；GL 上限恰好 2³¹−1、零余量 | `limits` 单测覆盖 + 反面对照 | 🔶 阶段 1–2 已做 |
| ⑦ | **接受"一次 draw"的适用边界**（可见 ≲1e5 时成立，再往上分批/LOD） | 容量由（轨道空间密度 × 视锥面积）决定，不由 n 决定 | 最坏（重绘）口径下 60 fps ≥159K 可见实例 | ⚠️ 已有标定 |
| — | **音频是独立的另一道墙**：常驻整段 PCM（48 kHz 立体声 float = 384 KB/s）→ 1e6 层 ≈ 0.19 TB | 与 ③ 同源的"窗口化"问题 | 播放流式化 | ❌ |

✅ **已修**（别重复踩）：位置改 double / 相机相对 float（float32 在 MYC 规模 15.26% 相邻对误差 > 0.01 砖、
primer 上 50.7% 相邻对是同一个点）；砖位置按 **65536 砖一块**存块相对 float（块内 ulp ≤ 0.008 砖，代价 0.00024 B/砖）。

## 5. 纪律（这些是铁律，不是建议）

1. **绝不静默截断**：计数/长度一律 int64；必须交给 32 位 API 时走 `fitsInt32`/`toInt32Checked`，
   装不下就 `LOG_E`。**本地造不出 2³¹ 层**（最大只有 3%），所以边界只承认**纯函数单测 + 反面对照**。
2. **零行为变化**：2³¹ 以下任何改动都必须让 ctest / 39 fixture 逐位 / **像素门槛 51/51** 全绿
   （`#0 阶段 2` 就是这么验收的：`adocao image` MYC 64×64 md5 相同）。
3. **像素/渲染类问题先出差异图再谈实验**；抓帧路径不许有"由帧时间反馈决定的量"。
4. **基线不入库、不放 `/tmp`**：像素基线在 `~/Projects/.ADOCAO/gate/baseline`，临时抓帧留工作区内。
5. **每条规模结论都要留"命令 + 数字 + 证据等级（实测/推导/外推）"**，并且**能重跑**。

## 6. 非目标

* 不重写渲染器、不换图形 API（Vulkan 版在 `../ADOCAV/`，是另一条线）。
* **不为 2³¹ 牺牲现有体验**：n ≤ 1e7 的谱，CPU/内存/加载时间不许变慢（D4 就是这条的守门员）。
* 不追"最大层数"这个数字本身：目标是**把 32 位假设清算干净**，让规模律变成可推导的。

* 门槛报"没装 Pillow"时用 `ADOCAO_GATE_PY=<带 Pillow 的 python3>`；**别在抓帧的同时跑别的抓帧**。
* **临时抓帧留在工作区内**（`build/gate-scratch`）—— 往工作区外写会被沙箱拒，门槛会报一整片假"不一致"。
* 手工试玩前 `scripts/make-app.sh`（`.app` 是快照，不会自动更新）。

**现成的测试钩子**（`adocao --help` 末尾那段；都可用于**负向对照**，别只测"正常路径"）

| 钩子 | 作用 |

| `ADOCAO_WINDOW_REQUIRE=1` | **窗口被放弃就 `LOG_E`** —— ① 的验收就靠它（大谱上已不响 ✅）|

* 容器/判据：`tests/charts/diag_*.adofai`（9 张，生成器 `tests/gen_adocao_charts.py` 确定性可重跑）+
  `adocao pack <谱> <out.adocao> --codec-report`。

**别踩**

1. **`docs/scale-1e8-to-2e9.md` §4 的 `strtod` 归因已经被证伪**（2026-10-15）：先复现再定位
   （`ADOCAO_WINDOW_KB` 4096→8192 二分 + `ADOCAO_WINDOW_DBG=1`），真因是 `parseNumber` 的
   **指数回退**（窗口在 `e`/`e±` 后用完 → 提交截断值 + 留下吃不掉的 `e` → 整窗 carry → `stuck()`）。
   **别把任何未复现的归因当结论往代码上套** —— 这条错误归因让 `parseNumber` 白改了一轮。
2. **"对拍测试永远绿"陷阱**：快路径一放弃，"快路径那次加载"**就是**旧路径 → 比输出永远相同。
   任何 require 钩子都必须配**反面对照**（喂一个"本该被拒"的输入，确认它真的喊）。
3. **A/B 要整块回退**：只回退改动里的一行会得出错误结论（AGENTS 里记着这次吃亏）。
4. `.adocao` v3 的 ① ② ⑤（`WrapDelta` / 正交 `Varint`/`RleVarint` / `FixedPoint`）**只落了诊断**，
   编码器还没写；⑥ 分块、⑧ `Derived` checkpoint 同理 —— 别以为"报里有判据"就等于"已经实现"。
5. `Timeline` 现在**对 >int32 层是明确拒绝**（`LOG_E`），不是静默坏；阶段 3 会把它变成真 64 位。
6. 刚做完 ImGui 1.92 升级（字体/DPI/`PushFont(font, LegacySize)`/`io.FontDefault`），
   由 ctest `font_cjk` 守着 —— 别把 `????` 那个坑再踩回来。
